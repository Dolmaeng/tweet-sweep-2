# 요구사항 명세 (SRS)

- 상태: v0.2 · 2026-09-17 · 질의응답(Q1~Q4) 반영. 전작 `tweet-sweep` SRS v0.3을 세션 방식으로 개정
- 표기: **[확정]** / **[미정→Qn]**(§10) / **[제안]**
- 상위 문서 `00-constitution.md` · 결정 근거 `../adr/`

## 1. 배경·목표
- 개인 X 계정(최대 3개)의 과거 게시물을 비용 0원으로, 계정 잠금 위험을 최소화하며 삭제. 속도보다 안전
- 부수 목표(우선순위): ① 안전 ② 에이전틱 코딩·오케스트레이션 학습 ③ LLM 내부 원리 ④ 웹/프론트/CS 기본기(확장 API·DOM·TS·IndexedDB) ⑤ 확장 가능 구조 ⑥ 블로그 소재
- 성공 기준: 대상 100% 삭제 · 계정 영구 정지 0회(일시 잠금은 복구 절차로 대응) · 비용 0원 · 다른 Windows PC에서 clone 후 재현

## 2. 범위
### 포함
- Chrome 확장(MV3). 실행 단위 = 현재 로그인 계정 1개 + 그 계정의 아카이브 1개 **[확정]**
- 아카이브 가져오기 → 인벤토리(IndexedDB) → `analyze` 보고서 → 필터 → `plan`(dry-run) → `run`(작업 탭에서 삭제) → 감사 로그·내보내기
- 대상 유형 v1: 원글, 답글, 미디어 포함 게시물 **[확정]**
- 대시보드 페이지(진행률·설정·로그) = 오케스트레이터 **[확정, ADR-0004]**
### 제외 (v1) — 확장 지점으로 예약
- 리포스트 취소 · 좋아요 취소 · 북마크 · DM · 팔로우 정리 · 아카이브 이후 게시물 보충 · 백그라운드(대시보드 닫힘) 실행 · 스토어 배포

## 3. 환경·전제
- Windows 11 Home · Chrome 152 · Edge 153 · Node.js LTS 설치 필요(WXT 빌드, M1 첫 작업) **[확정]**
- 계정 규모 합계 1만~3만 건. 계정별 아카이브 zip 보유. 사용자가 해당 계정으로 Chrome에 로그인한 상태에서 실행
- X 웹 클라이언트 삭제 한도는 비공개. 공식 API 50/15min을 상한 가정으로 사용

## 4. 기능 요구사항
| ID | 요구사항 | 상태 |
|---|---|---|
| FR-01 | 아카이브 가져오기: 파일 선택(zip 또는 `tweets.js`·`tweets-part*.js`·`account.js`) → 로컬 파싱 → IndexedDB. DM 등 다른 파일은 읽지 않음 | 확정 |
| FR-02 | 유형 분류: 원글 / 답글(`in_reply_to_status_id`) / 리포스트(`RT @`) / 미디어(`extended_entities`) | 확정 |
| FR-03 | 계정 일치 검증: 아카이브 accountId ≠ 세션 `twid` id면 실행 거부 | 확정 |
| FR-04 | 필터 파이프라인: 전체 · 기간 · 키워드/정규식 · 유형 · 보존 목록 · 지표 임계. 조합 가능, 파일 1개로 새 필터 등록 | 확정 |
| FR-05 | `analyze`: 유형별 건수 · 연도 분포 · 미디어 수 · 프리셋별 예상 소요 보고서(화면 + CSV) | 확정 |
| FR-06 | `plan`: 필터 결과 목록·요약. CSV 내보내기. 기본 동작 = dry-run | 확정 |
| FR-07 | `run`: 위험 고지 동의 + 확인 + 건수 상한 후 시작. 대시보드가 작업 탭을 만들고 항목별로 실행기 호출. 일시정지/중단 버튼 | 확정 |
| FR-08 | 실행기 인터페이스 `Executor.delete(postId) → ok / gone / blocked / error`. 기본 `ui-click`, `graphql-replay`는 예비(ADR-0005). 설정에서 전환 | 확정 |
| FR-09 | 차단 신호 감지: 429·"Rate limit exceeded"(webRequest 관측 또는 응답 파싱) · 오류 토스트 · 로그인 페이지 리다이렉트 · 잠금/인증 페이지 → 회로차단 | 확정 |
| FR-10 | 페이싱: 프리셋·무작위 간격·활동 시간대·일일 상한·워밍업. 하드 상한 코드 고정 | 확정 |
| FR-11 | 감사 로그: 항목별 시각·실행기·결과·신호·소요. JSONL/CSV 내보내기 | 확정 |
| FR-12 | 스냅샷: 삭제 전 텍스트·메타 보존(인벤토리 원본 JSON) | 확정 |
| FR-13 | 계정별 상태 분리: `twid` id 기준으로 인벤토리·작업·로그 분리 | 확정 |
| FR-14 | 설정 화면: 프리셋·활동 시간대·일일 상한·실행기·메뉴 라벨(언어)·셀렉터 오버라이드 | 확정 |
| FR-15 | 위험 고지 첫 화면 + 동의 체크. 매 `run` 시작 시 요약 재표시 | 확정 |
| FR-16 | 액션 확장 지점: `unretweet`·`unlike`를 같은 실행기 인터페이스로 추후 추가 | 확정 |
| FR-17 | LLM 분류 필터(보존/삭제 추천, 사람이 승인) | 제안(v2) |

## 6. 안전 정책 (수치)
- 가정 한도 50/15min. 프리셋 **[제안]**, 활동 시간대 14h 기준

| 프리셋 | 건당 간격(무작위) | 15분 사용률 | 일일 | 1만 건 | 3만 건 |
|---|---|---|---|---|---|
| `cautious` | 60~120s | ≈20% | ≤400 | ≈25일 | ≈75일 |
| `normal` | 30~60s | ≈40% | ≤800 | ≈13일 | ≈38일 |
| `brisk`(기본) | 25~35s | ≈60% | ≤1,500 | ≈7일 | ≈20일 |

- 기본 프리셋 `brisk`(사용자 선택 Q3). 워밍업·자동 하향은 그대로: 첫날 ≤50건 → 3일간 상한 50%→100%. 같은 날 차단 2회면 `normal`로 하향 후 다음 날 재시작 **[확정]**
- 세션 최대 3h 후 30~60분 휴식. 5% 확률로 5~15분 긴 휴식
- 회로차단: 429/차단 문구 → 세션 종료(reset+여유 후 사람이 재시작), 같은 날 2회면 다음 날까지 정지 + 프리셋 한 단계 하향 · 로그인/잠금 페이지 → 즉시 종료 · 연속 실패 3회 → 종료
- 하드 상한(코드 고정): 15분 ≤30건 · 일일 ≤1,500건 · 최소 간격 20s
- 실행 전 체크: 로그인 상태, `twid` 일치, 활동 시간대, 일일 잔여

## 7. 제약·가정
- X 웹 클라이언트는 예고 없이 바뀜(DOM·문구·GraphQL 식별자) → 실행기 2종, 설정 오버라이드, 계약 테스트
- 백그라운드 탭 타이머 제한 → 작업 탭은 별도 창 또는 활성 유지. 절전 모드 시 중단
- 합성 클릭 `isTrusted=false`를 X가 검사하기 시작하면 UI 실행기 파손 → `chrome.debugger` 입력 이벤트 대체안
- 아카이브 이후 게시물은 v1 범위 밖

## 9. 위험 관리

|---|---|
| 계정 일시 잠금 | 저속·워밍업·활동 시간대. 잠금 시 사람이 해제, 프리셋 하향 후 재개 |
