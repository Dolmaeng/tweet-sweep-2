# 헌장 (Constitution)

- 버전 2.0 · 2026-09-17 · `tweet-sweep`(공식 API 방식) 헌장을 세션 방식에 맞게 개정. 변경은 ADR로만
- 원칙은 요구사항·설계·코드보다 우선한다

## P0. 수용한 위험을 숨기지 않는다
- 이 도구는 사용자가 로그인한 x.com 세션 안에서 사람이 하는 삭제를 대신 수행한다. X 약관의 자동화 제한에 저촉될 수 있고 계정 잠금(전화 인증) 가능성이 있다
- 사용자는 이 위험을 알고 선택했다(2026-09-17, ADR-0001). 문서와 대시보드 첫 화면에 위험 고지를 유지한다
- 위험을 낮추는 길은 하나: 사람보다 느리고 규칙적이지 않게, 차단 신호가 오면 즉시 멈춘다

## P1. 사람 행동 모사, 최소 속도
- 실행기는 ADR-0005로 정한다. 어떤 실행기든 아래 규칙을 따른다
- 간격 무작위, 활동 시간대 제한, 일일 상한, 워밍업. 하드 상한은 코드 고정, 설정으로 초과 불가
- 차단 신호(429·"Rate limit exceeded"·오류 토스트·로그인 페이지·잠금 안내) → 즉시 중단. 사람이 확인한 뒤 재개
- 탭 1개·계정 1개만 실행. 실행 중 같은 계정으로 다른 활동 최소화 권고

## P2. 모든 것은 로컬
- 서버 없음. 아카이브·인벤토리·로그는 확장 저장소(IndexedDB)에만. 외부 전송 코드 0
- 권한 최소: x.com 호스트, storage, tabs, scripting, (관측용) webRequest. 원격 코드 로드 없음

## P3. 기본은 dry-run
- 기본 동작은 대상 목록 생성·미리보기. 실제 삭제는 명시적 시작 + 확인 + 건수 상한

## P4. 되돌릴 수 없는 작업 전 보존
- 아카이브 원본은 읽기 전용. 삭제 대상의 텍스트·메타를 인벤토리에 보존. 결과는 감사 로그로 기록·내보내기

## P5. 멱등·재개 가능
- 상태의 단일 원본은 IndexedDB. 브라우저 종료·탭 닫힘 후 재실행 안전. 같은 항목 두 번 시도하지 않음. 이미 없는 글은 완료 처리

## P6. 관측 가능
- 대시보드에 진행률·잔여 예상·최근 오류·다음 실행 시각. 감사 로그 JSONL/CSV 내보내기

## P7. 확장 지점을 먼저 설계
- 실행기(UI 클릭 / GraphQL 재전송) · 필터 · 액션(삭제 / 리포스트 취소 / 좋아요 취소)을 인터페이스로 분리

## P8. 이식성
- `git clone` 후 두 경로: 빌드(Node) 또는 릴리스 zip → `chrome://extensions` 개발자 모드 → 압축해제된 확장 로드
- Chrome 우선, Edge 동작 유지

## P9. 문서 규칙
- 개조식 불렛·간결·승계 가능·틀린 내용 0·읽는 비용 최소. 결정은 ADR, 방법론 선택엔 이유. 작업 로그는 일자별. 확정/미정/제안 표기
