# ADR-0005: 실행기 — 기본 `ui-click`, `graphql-replay`는 예비

- 상태: 확정(Q2) · 2026-09-17

## 맥락
- 세션 방식 삭제 구현 2종. ① UI 클릭: 글 페이지를 열고 실제 메뉴·확인 버튼을 누름 ② GraphQL 재전송: 웹 클라이언트의 `DeleteTweet` 요청을 쿠키·헤더 붙여 직접 전송(Cyd·대다수 도구)
- 사용자 우선순위: 무료 경로 안에서도 잠금 위험 최소

## 결정
- `Executor` 인터페이스 1개, 구현 2개. 기본값 `ui-click`. `graphql-replay`는 설정에서 명시 전환 시만 사용, 식별자는 세션 트래픽 관찰로 갱신
- 두 실행기 모두 같은 페이싱·회로차단을 거침(P1)

## 이유
- UI 클릭은 네트워크 요청을 X 클라이언트가 스스로 생성 → 트랜잭션 헤더·텔레메트리 포함, 사람과 구별 불가. 식별자 회전 무관
- GraphQL 재전송은 트랜잭션 헤더를 생략(2026-09 기준 동작)하고 식별자 회전을 따라가야 함 → 파손·탐지 신호 위험이 UI보다 큼. 응답 해석이 정밀하고 빠른 점은 UI 파손 시 예비로 살림
- 건당 1~3s 추가 지연은 20s 이상 페이싱 대비 무시 가능

## 대안과 기각 사유
| 대안 | 기각 사유 |
|---|---|
| GraphQL 기본 | 위 위험. 속도 이점은 페이싱 때문에 의미 없음 |
| UI만 | DOM 변경 시 대안 없음 |

## 결과·후속
- 셀렉터·메뉴 라벨(`삭제`/`Delete`)은 설정 오버라이드. 합성 클릭 검사(`isTrusted`) 등장 시 `chrome.debugger` 입력 이벤트 실행기 추가 검토
