# ADR-0004: 오케스트레이터는 확장 대시보드 페이지, 서비스 워커는 최소

- 상태: 확정 · 2026-09-17

## 맥락
- MV3 서비스 워커는 유휴 30s 후 종료, 이벤트 핸들러 1회 최대 5분. `chrome.alarms` 최소 주기 30s(Chrome 120+). 오프스크린 문서는 runtime 메시징만 가능
- 삭제 루프는 수십 분~수 시간 지속, 간격 30~180s

## 결정
- 실행 루프·상태 관리·UI는 확장 페이지(`dashboard.html`, 탭으로 열림)가 담당. 페이지가 열려 있는 동안만 실행
- x.com 작업 탭은 대시보드가 `chrome.tabs`로 만들고 콘텐츠 스크립트에 명령 전달. 서비스 워커는 메시지 중계·설치 처리만
- 백그라운드(대시보드 닫힘) 실행은 v1 범위 밖. 필요 시 `alarms` 기반으로 추후 추가

## 이유
- 수명 관리가 명시적: 페이지가 보이면 돌고, 닫으면 멈춤 → 사용자가 항상 상태를 봄(P6)
- 서비스 워커 생존 꼼수(포트 keepalive 등) 불필요. 디버깅 쉬움
- 대시보드가 곧 웹 프론트 학습 산출물

## 대안과 기각 사유
| 대안 | 기각 사유 |
|---|---|
| 서비스 워커 + alarms 루프 | 상태 복원·중복 실행 방지 복잡, 사용자 가시성 낮음. 추후 옵션 |
| 오프스크린 문서 | tabs/scripting API 접근 불가 |
| 콘텍스트 스크립트 단독 루프 | 페이지 이동 시 상태 소실, x.com 탭 닫히면 끝 |
