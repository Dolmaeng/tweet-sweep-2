# ADR-0010: 스윕 모드 보존 필터 — 지우지 않을 글을 카드에서 판정

- 상태: 확정 · 2026-09-18 · 사용자 요청(UI 명세 제시). ADR-0009의 "필터 없음"을 개정

## 맥락
- ADR-0009는 스윕 모드를 "전부 삭제"로 못박았다. 근거는 당시 용도가 **다른 계정 전체 삭제**였다는 것
- 용도가 늘었다: 쓰던 계정에서 남길 글(반응이 있던 글, 특정 키워드가 든 글)만 두고 나머지를 정리
- 제약: 스윕은 목록을 만들지 않는다. 판정 재료는 **타임라인 카드 DOM에 보이는 것**뿐이다
- 아카이브에는 '내가 좋아요/리트윗/북마크한' 상태가 없다(legacy `favorited`·`retweeted`는 아카이브에서 항상 false). 명세의 8개 조건을 전부 만족하는 곳은 타임라인 카드뿐 → **스윕 모드 전용**(사용자 확정 2026-09-18)

## 결정
- 필터는 **보존 필터**다. 조건에 걸리면 후보에서 빼기만 한다. 새로 지우는 대상을 만들지 않는다
- 판정은 `core/sweep-filter.ts` 순수 함수 `isExcluded(item, filter)`. 입력은 `TimelineItem` 하나뿐
- 카드에서 읽는 신호(`executors/timeline-scan.ts`)
  - 내가 한 액션: 누른 뒤 바뀌는 testid `unlike`·`unretweet`·`removeBookmark`의 존재
  - 수치 1 이상: 액션 버튼의 `aria-label`("좋아요 12개")이나 버튼 텍스트에 숫자가 있는지. **수를 파싱하지 않는다** — 축약 표기("1.2천")·로캘에 흔들리지 않게
  - 미디어: `tweetPhoto`·`videoPlayer`·`videoComponent`. 인용글(`[role="link"]`) 안에 있으면 내 미디어가 아니다 → `ownMedia` / `hasMedia` 구분
  - 멘션: 답글 카드이거나 본문이 `@`로 시작. X는 답글 카드에서 맨 앞 @핸들을 본문에 넣지 않고 "…에게 보내는 답글"로 따로 그리므로 둘 다 본다(사용자 확정)
  - 답글 안내 판정은 본문(`tweetText`)과 액션 바(`[role="group"]`)를 떼어낸 뒤 한다. 액션 바의 "답글 3개" 버튼이 모든 카드를 답글로 만들기 때문
- 필터는 설정(`sweepFilter`)에 저장해 새로고침·재개 후에도 유지. 실행 중에는 `fieldset disabled`로 잠근다
- 이어서 실행할 때도 **지금 화면의 필터**를 쓰고, 작업 기록(`job.filterSpec`)을 그 값으로 맞춘다

## 완료 판정을 고친 이유 (중요)
- 보존한 글은 지워지지 않으므로 타임라인 맨 위에 **영구히 쌓인다**. 후보 없는 화면이 계속 나온다
- 기존 규칙(스크롤 3회 → 새로고침 → 스크롤 3회 → 완료)을 그대로 두면 보존 글 벽이 세 화면만 넘어도 **거짓 완료**로 멈춘다
- 수정: 스캔에 **처음 보는 글이 하나라도 있으면** 아직 다 훑지 못한 것으로 보고 빈 횟수를 0으로 되돌린다. 이번 실행에서 본 id를 모두 기억하므로, 새로고침으로 맨 위에 돌아가도 "새 카드"로 오인하지 않는다 → 사다리가 정상 종료
- 필터가 켜져 있으면 삭제 후 맨 위로 되돌아가지 않는다. 돌아가면 보존 글 벽을 매번 다시 스크롤해야 하고, 그 비용이 삭제할수록 커진다

## 대안
| 대안 | 내용 | 판단 |
|---|---|---|
| 아카이브 모드에도 같은 필터 | 계획 화면에 동일 패널 | 기각: 8개 중 '내가 ~한' 3개를 판정할 수 없어 반만 동작하는 UI가 된다 |
| 수치를 숫자로 파싱 | "1.2천" → 1200 후 임계값 비교 | 기각: 명세가 요구하는 건 "1개 이상"뿐. 축약·로캘 파싱은 얻는 것 없이 깨질 지점만 늘린다 |
| 필터를 실행 중 변경 허용 | 돌면서 조건 조정 | 기각: 무엇을 왜 지웠는지 사후에 설명할 수 없다(헌장 P6) |
| 보존 글을 skip 집합에 넣기 | 이미 있는 재시도 방지 장치 재사용 | 기각: skip은 "시도했지만 실패"의 뜻. 섞으면 실패 통계가 오염된다 |

## 위험·한계
- **북마크 수**는 X가 카드에 숫자를 붙일 때만 읽힌다. 안 붙이면 `hasBookmarks`는 늘 false → 그 조건이 조용히 무효가 된다. 라이브 검증 필요
- 답글 안내·사회적 맥락은 문구 기반 판정이라 X의 문구 변경에 취약하다(기존 고정글·리포스트 판정과 같은 성질)
- 링크 미리보기 카드 제목에 "답글"이 들어가면 멘션으로 잘못 볼 수 있다. 보존 쪽으로 기우는 오류라 삭제 사고로는 이어지지 않는다
- 필터를 강하게 걸면 삭제 1건당 스크롤이 늘어 실질 속도가 떨어진다. 안전 한도(ADR-0008)는 그대로다
