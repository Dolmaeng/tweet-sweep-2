# 2026-09-20

## 잔여가 남았는데 멈춰 선다 — 남의 예산으로 브레이크를 밟고 있었다 (T43)

### 사용자 보고
- "지금은 삭제하지 않고 기다리는 중입니다. 이유: 예산 소진 — 창 리셋 대기. 재개 예정 오전 11:35 / X 예산(CreatorStudioTabBarItemQuery): 한도 50, 잔여 13, 리셋 562s < 이 메세지는 왜 뜨는거야? 한도에 잔여가남아있는데도. 그리고 저 한도의 기준이뭐임?"

### 세 가지가 섞여 있었다
1. **잔여 13에서 멈춘 것은 설계대로다.** `shouldWaitForReset`은 `remaining < (1−u)·L`에서 물러난다. 빠름(u=0.7)·한도 50 → 문턱 15. 0까지 쓰고 429를 맞지 않으려는 예비분이다
2. **발목을 잡은 연산이 `CreatorStudioTabBarItemQuery`였다.** 삭제도 읽기도 아니다 — ADR-0014가 관측을 "모든 GraphQL"로 넓혔고, `tightestBucket`이 그중 가장 좁은 걸 고르니, X가 자기 UI 그리려고 보낸 요청의 한도 50이 삭제 루프의 브레이크가 됐다. 삭제를 멈춰도 그쪽 잔여는 회복되지 않는다
3. **헤더가 562초라는데 15분을 잤다.** `scheduler.ts`가 `now + budget.windowSec*1000`으로 기다렸고, `windowSec`은 `budget.ts`가 항상 가정값 900으로 넣는다. 관측한 리셋은 표시에만 쓰이고 버려졌다. 창 중간에서 멈춘 지점에 창 길이를 또 더하니 흘러간 시간을 두 번 센 것

### 고친 것 (ADR-0015)
- `core/budget-buckets.ts`에 `PACED_OPERATIONS` 화이트리스트. 삭제 뮤테이션 4개 + 지우기 전 읽는 화면들만. `background.ts`가 그 밖은 `BUDGET`·`RATE_LIMIT`으로 보내지 않는다 (무관한 429가 회로차단기를 식히던 것까지 같이 막힌다)
- `resetAtMs(b) = atMs + resetSec·1000`. `RunSnapshot`·`BudgetSnapshot`에 실어 `decide`가 그 시각까지만 기다린다. 모르면 종래대로 창 길이

### 왜 블랙리스트가 아니라 화이트리스트인가
틀리는 방향이 다르다. 화이트리스트가 연산을 놓치면 화면이 "예산 미관측"이 되고 ADR-0014의 페이지 단위 백오프가 받아낸다 — 안전망이 있다. 블랙리스트가 놓치면 이 증상이 그대로 남는다 — 안전망이 없다.

### 함정
- `resetSec`을 그대로 넘기면 안 된다. 관측 시점 기준 잔여라서, 절대 시각으로 바꿔 넘기지 않으면 같은 실수를 반복한다
- 리셋 시각이 이미 지났으면 `now + 1초`로 내려 잡는다. 다음 회차에 `freshBuckets`가 만료 버킷을 버려 잔여가 `null`이 되고 삭제가 재개된다
- 예비분(`(1−u)·L`)은 건드리지 않았다. 더 끝까지 쓰려면 프리셋을 질주(문턱 2.5)로 올리는 게 정해진 통로다
- 테스트 166개, 빌드 통과
