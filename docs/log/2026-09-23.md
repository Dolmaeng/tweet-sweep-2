# 2026-09-23

## 답멘만 지워지고 있었다 — X가 프로필 탭을 갈랐다 (T44)

### 사용자 보고
- "이상하게 이 머신은 네비게이션 바의 왼쪽에서 두번째 버튼인 'Replies'탭을 활성화해서 삭제하는거같아. 그러면 답멘만 지우는거야;;"
- "All을 활성화해서 조회되는 타임라인에서 트윗을 최신꺼부터 순차적으로 삭제하도록 바꿔. 그리고 미디어(사진, 동영상 모두), 리포스트 또한 All 탭에서 삭제하도록 로직을 수정해. 답멘관련 필터를 걸었을 때만 Replies 탭에서 지우도록 설정해"

### 라이브로 확인한 것 (x.com/gujik_man, ko)
DOM을 직접 읽었다. ADR-0009을 쓴 2026-09-17과 탭 구조가 다르다.

| 탭 | href | 내용 |
|---|---|---|
| 게시물 / 전체 | `/<handle>` · `/<handle>/all` | 맨 왼쪽, `aria-haspopup="menu"` 드롭다운 |
| 답글 | `/with_replies` | **답글만** (예전엔 원글+답글) |
| 재게시 | `/reposts` | 리포스트만 |
| 미디어 | `/media` | 미디어 글만 |

- 드롭다운 항목은 href 없는 `div[role="menuitem"]`: 전체 · 게시물 · 하이라이트 · 정렬 기준
- **"전체"를 고르면 주소가 `/<handle>/all`이 되고, 그 주소로 직접 들어가도 전체가 선택된다** → URL 한 번이면 끝난다
- 정렬 하위 메뉴는 `[role="menuitemradio"]` 둘: "최신 순서"(기본 체크) · "인기"
- 재게시 취소: `[data-testid="unretweet"]` → `[data-testid="unretweetConfirm"]`("재게시 취소"). 확인 시트 없음

즉 스윕이 열던 `with_replies`가 답글 탭이 되어 있었다. 사용자가 본 그대로다.

### 고친 것 (ADR-0016)
- 기본 스캔 페이지 `/<handle>/all`. `sweepTabOf(filter)`가 멘션 모드 `only`일 때만 `/with_replies`를 준다. '멘션 제외'는 답글 아닌 글을 지우겠다는 뜻이라 전체 탭이 맞다
- `executors/profile-tabs.ts`: 주소로 안 되면 드롭다운을 열어 "전체"를 누른다. 판정은 선택된 탭의 href(`/all`로 끝나는가)
- **주소가 그 탭이 아니면 실행을 멈춘다.** 탭 줄을 못 읽는 것(계속)과 엉뚱한 타임라인에 서 있는 것(중지)은 다르다
- 정렬은 실행당 한 번만 "최신 순서"로 맞춘다. 이미 맞으면 아무것도 누르지 않는다
- 내가 누른 리포스트는 `undoRepost`로 재게시 취소. FR-18의 "리포스트 제외"를 뒤집었다

### 리포스트에서 조심한 것
- **caret 메뉴를 절대 열지 않는다.** 리포스트 카드의 caret은 원작성자 메뉴(언팔로우·차단·신고)다. 2026-09-17에 그 메뉴가 열려 연속 오류로 정지한 적이 있다
- 카드는 링크가 일치하는 것만 쓴다(`findCardArticle`). 삭제 쪽의 "화면에 카드가 하나뿐이면 허용" 완화를 타임라인에 두면 **옆 사람의 재게시를 취소**한다
- 안전 판정이 바뀐다: 리포스트 카드의 permalink handle은 원작성자다. handle 비교가 통하지 않으므로 `unretweet` 버튼의 존재(`retweeted`)를 "내가 눌렀다"는 증거로 쓴다. 없으면 손대지 않는다
- 되돌릴 스위치는 이미 있다 — 보존 필터의 "내가 리포스트한 글"

### 함정
- 메뉴는 합성 Escape 이벤트로 안 닫힌다. `#layers`의 전면 배경을 눌러야 닫힌다. 열어 둔 채 두면 스크롤도 카드 클릭도 막힌다
- 리포스트의 `postId`는 원글 id라, "최신부터"가 리포스트에 대해서는 내가 누른 시각이 아니라 원글 작성 시각 기준이 된다. 순서만의 문제이고 결국 다 치운다
- 테스트 195개, 빌드 통과
