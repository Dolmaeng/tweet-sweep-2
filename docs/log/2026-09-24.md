# 2026-09-24

## 분석 표의 "삭제 대상"은 대상이 아니라 상한이었다

### 사용자 질문
- "전체 201 / 원글 98 / 답글 9 / 리포스트 94 (v1 제외) / 미디어 포함 167 / 삭제 대상(원글+답글) 107 — 이거 분류 기준이 뭐야? Mutually exclusive 하게 분류한거 맞아? 미디어는 원글에 포함되는거야? 왜 삭제대상에 미디어와 리포스트는 없어?"

### 확인한 것
- 종류는 `classify()`(`core/archive/parse.ts`)의 if-else 사슬이라 **상호배타가 맞다**. RT 판정이 먼저라 리포스트한 답글은 리포스트로 센다. 98+9+94=201로 합이 맞는다
- `withMedia`는 종류가 아니라 **교차 속성**이다. 세 종류에 걸쳐 세므로 167이 삭제 상한 107을 넘어도 모순이 아니다 — 리포스트 항목도 원글의 media entity를 물고 있으면 센다
- 리포스트가 대상에 없는 이유: `DEFAULT_KINDS = ['post','reply']`이고 종류 선택지에 `retweet`이 아예 없다. 리포스트는 삭제가 아니라 재게시 취소이고 스윕 소관이다 (ADR-0016)

### 고친 것
- 107은 `byKind.post + byKind.reply`라 **보존 필터·기간을 적용하기 전 숫자**다. 실제 계획 수는 `PlanRun`의 `selectTargets`가 정한다. "삭제 대상"이라는 이름이 확정된 계획처럼 읽혀 라벨을 바꿨다
  - 분석 표: `삭제 대상(원글+답글)` → `삭제 가능 최대(원글+답글)` + "보존 필터·기간 적용 전"
  - 홈 계정 표: `대상(원글+답글)` → `최대 대상(원글+답글)`
  - 변수 `target` → `maxTarget`, CSV 키 `target_v1(posts+replies)` → `max_target(posts+replies)`
  - "속도별 예상 소요"도 그 상한 기준이라는 말을 붙였다 — 표가 상한으로 계산하면서 그렇게 안 적으면 소요 시간까지 확정처럼 읽힌다

### 함정
- 분류 질문에 "미디어가 어느 종류에 속하나"가 나오는 건 표가 **배타적 분류 3줄과 교차 속성 1줄을 같은 모양으로** 늘어놓기 때문이다. 줄 모양이 같으면 합이 맞는 축과 안 맞는 축을 구별할 수 없다
